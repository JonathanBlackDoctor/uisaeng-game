# 전공별 수련·직업 사건

`game/src/specialty-depth.ts`의 `specialty-depth-provisional-1`은 가상 게임 콘텐츠와 조정값이다. 실제 진료 지침, 전공별 수입, 의료사고·사망·분쟁 확률을 나타내지 않는다. 정식 규칙 승인으로 기록하지 않는다.

26개 전공마다 수련 사건 1개와 직업 사건 1개가 있다. 사건마다 무료 선택 2개와 유료 선택 1개를 제공한다. 총 52개 사건, 156개 선택이다. 학습비는 현실 가격을 조사한 값이 아닌 일회성 게임 지출이다. 원본 연구 자료는 사용하거나 수정하지 않았다.

## 선택이 남기는 차이

- `effects`: 즉시 적용할 건강·행복·지식·관계 변화. 추가 상담·기록·교대 지연의 시간 부담은 결과 문장과 건강·행복 변화로 표현한다. 현재 계약에는 별도 시간 필드가 없다.
- `skill`: 이번 선택에서 얻는 전공 숙련 증가량. `safety`: 이번 선택에서 얻는 안전관리 증가량. 둘 다 현실 자격이나 사고 확률이 아니다. 누적값은 통합 엔진에서 각각 0~100으로 제한한다.
- `cash`: 선택 시 한 번 적용하는 원 단위 증감. 비용과 결과 문장의 금액은 일치한다. 무료 대안이 매 사건에 있다.
- `followUp`: 선택 3개월 뒤 기록에 남길 한 문장. 이 데이터 자체에는 추가 스탯 효과나 자동 성공 판정이 없다.

무료 선택끼리도 차이가 있다. 시간을 더 쓰는 직접 검토는 숙련·지식을 얻는 대신 건강 부담이 생기고, 협업·역할 분담은 관계와 안전관리에 더 무게를 둔다. 유료 실습은 숙련 증가가 크지만 비용과 개인 시간이 들며 안전관리 증가가 항상 가장 크지는 않다. 실제 진료 결과를 좋음·나쁨으로 판정하는 선택은 만들지 않았다.

`monthly`의 봉직 수입·개원 매출·운영비·건강·행복 추가값과 `clinicSetup`은 전공 전체에서 0이다. 기존 경제 기본값을 바꾸거나 전공의 현실 수익 순위를 암시하지 않는다. `monthly.health`와 `monthly.happiness`는 이후 값을 조정할 경우 3개월 간격 효과로 적용하며, 월별 금전값과 구분한다.

## 통합 계약과 한계

공통 파일을 가져오거나 수정하지 않는 독립 모듈이다. `DepthChoice`, `DepthEpisode`, `SpecialtyDepth`, `SPECIALTY_DEPTH`, `DEPTH_RULES`를 내보낸다. 전공 키는 `career.ts`의 26개 `SPECIALTIES.id`와 같다. 사건·선택 ID는 전역에서 겹치지 않으며 선택 ID에는 사건 ID가 접두사로 붙는다.

통합 담당자는 선택 직전에 잔액을 확인해 감당할 수 없는 유료 선택을 막고 무료 선택을 계속 제공해야 한다. 사건 재발생·선택 중복 적용·예약된 후속 기록·저장복구는 엔진에서 처리해야 한다. 유료 선택의 참가비만 일회성으로 차감하고 실습 기간을 별도 월 진행으로 중복 계산하지 않는다. 실제 전공과 근무 형태가 어떤 시설을 운영할 수 있는지에 관한 제도 모델은 이 모듈의 범위 밖이다.

숙련·안전관리의 누적과 업무 결과 연결, 인물별 변화, 후속 로그의 예약은 아직 이 데이터만으로 실행되지 않는다. 따라서 이 파일의 완료가 게임 통합 또는 게임 전체 완성을 뜻하지 않는다.

## 확인 결과

Node v24.19.0의 TypeScript 타입 제거 실행으로 모듈을 불러와 다음을 확인했다.

- 26개 전공 키가 `SPECIALTIES`와 일치한다.
- 52개 사건에 각각 서로 다른 효과의 3개 선택이 있고, 모두 무료·유료 선택을 포함한다.
- 사건·선택 ID 208개가 겹치지 않는다.
- 유료 선택 52개의 수치와 문장 속 금액이 일치한다.
- 효과 키는 건강·행복·지식·관계만 사용하며 값은 유한수다. 금전은 안전한 정수이고 숙련·안전관리는 0~100 안의 정수다.
- 모든 월 추가값과 개원 추가비가 0이다. 선택 문구는 최대 17자, 사건 본문은 최대 66자다.
