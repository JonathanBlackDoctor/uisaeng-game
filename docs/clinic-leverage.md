# 병원 확장과 레버리지

2026-10-14 사용자 요청: “병원을 더 키울 수 있고 그대신 엄청난 위험 부담을 짊어지게 되는 레버리지도 구현하자”. 확장과 큰 손실 위험의 연결은 승인된 방향이다. 아래 금액·금리·확률·기간은 `game/src/clinic.ts`의 `clinic-leverage-provisional-v1` 시험 설정이며 정식 규칙 승인이나 현실 의료기관의 자료가 아니다.

개원 후 ‘병원 운영’에서 확장 조건을 확인한다. 중요 선택으로 시간이 멈추며, 대출과 시설 투입은 ‘대출받고 확장하기’를 선택해야 실행된다. 취소·열기·새로고침은 돈이나 위험 추첨을 바꾸지 않는다. 기존 저장에는 소급 대출·확장·위험을 추가하지 않는다.

| 확장 후 규모 | 추가 자기자금 | 추가 대출 | 기본 월 매출 | 기본 월 운영비 | 전체 대출 연금리 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 확장 의원 | 2천만원 | 1.8억원 | 3,600만원 | 2,400만원 | 9% |
| 중형 병원 | 6천만원 | 6억원 | 1억원 | 6,700만원 | 13% |
| 대형 병원 | 1.5억원 | 18억원 | 2.6억원 | 1.75억원 | 18% |

수치는 추가 투자액이며 매출·운영비는 해당 규모의 총액이다. 기존 물가·급여 지수가 별도로 반영된다. 시설 장부가 증가는 각각 1.4/4.5/11억원으로, 투입액 전부가 자산으로 남지 않는다. 대출금은 현금으로 남지 않고 시설로 들어간다. 재확장은 12개월 뒤 가능하며, 미납이나 위기·자기자금 부족 때는 계약할 수 없다.

기존 포트폴리오 이자 누적을 그대로 이용하되 확장 규모에 따라 전체 대출에 해당 금리를 적용한다. 이자를 중복 부과하지 않는다. 매월 현재 부채 한도에서 누적 확장 대출액/120과 현재 월 이자 예상액을 합친 만큼 상환한다. 미납 필수 지출이 있으면 상환하지 않고 위기로 진입한다. 일부 상환하지 못한 원금은 부채에 남으며 미납으로 다시 더하지 않는다. ‘매달 남는 돈’과 월 예산에도 필수 상환을 반영한다. 상환액은 부채 감소이며 운영비로 중복 집계하지 않는다.

3개월마다 독립 저장 시드로 불황을 추첨한다. 단계별 확률은 19/26/33%, 불황은 6개월, 기본 매출 감소는 40/55/70%다. 실제 개인 위험 확률이 아니다. 고정 운영비는 줄지 않는다. 돈이 남는 기간에는 매출 확대의 이익을 얻지만 적자에는 현금·자산을 소진한다. 직원 증가를 플레이어 개인의 누적 진료 건수로 환산하지 않는다.

원리금 상환 부족, 미납 또는 3개월 연속 적자 때 일반 소액 대출 선택보다 병원 위기를 먼저 연다. 대응은 규모 축소·폐업, 그리고 미납 없이 다음 운영비와 원리금을 감당할 현금이 있을 때만 더 버티기다. 버티기는 건강 -3·행복 -5, 적자가 지속되면 3개월 뒤 다시 판단한다. 즉시 상환 불능은 유예 중에도 다시 선택을 요구한다.

축소하면 마지막 확장 시설을, 폐업하면 최초 의원 시설까지 처분한다. 장부가의 45%만 회수하여 미납과 부채부터 갚는다. 처분 손실과 남은 빚을 기록하고, 폐업 뒤에는 봉직의로 전환한다. 파산 면책이나 부채 삭제 기능은 없다. 축소 후 해당 규모의 금리로, 폐업 후 기존 일반 대출 금리로 돌아간다. 확장 병원은 은퇴 전에 정리 선택을 거친다. 기존 비확장 의원의 은퇴 방식은 이 요청에서 바꾸지 않았다.

구현: `clinic.ts`, `ClinicPanel.tsx`, `contracts.ts`, `career-runtime.ts`, `economy.ts`, `portfolio.ts`, `finance-view.ts`, `CareerPanel.tsx`, `LifestylePanel.tsx`. 선택필드 `GameState.clinic`으로 저장 호환을 유지하고 거래·결산 중복, 시설 자산·시드·월 범위를 검사한다.
