# 전공과 능력 시너지 · 2026-10-14

사용자 요청: “몇배로 증폭되는 구조 만들어”. 후속 요청 “단순 숫자로 정해놓지 말고, 수치에 따라 지수가 달라지며 지수적으로 달라지게 수치 조정해”에 따라 기존 최대 3배의 선형식을 지수식으로 교체했다. 곡선의 계수와 전공별 조합은 조정 가능한 provisional 게임 설정이며 현실의 생산성·수입·의료 결과에 대한 사실이나 확률이 아니다.

26개 전공마다 판단력·술기·소통·연구력·운영력·자기관리 중 2~3개를 연결한다. 예를 들어 외과는 술기와 판단력, 정신건강의학과는 소통과 자기관리, 진단검사의학과는 연구력과 운영력이다. 각 관련 능력의 **현재 수행력/100**의 기하평균을 적합도 `f`, 전공 숙련/100을 `m`이라 한다. 두 값의 범위는 0~1이다.

지수는 `E = f² × (1 + 3fm)`, 배율은 `2^E`다. 능력과 숙련의 교차항이 지수에 들어가므로 둘을 함께 키울수록 증가폭이 커진다. 30 이하 또는 85 이상에서 끊는 구간과 별도의 최대 배율 제한은 제거했다. 내부 배율은 반올림하지 않으며 화면에만 소수 첫째 자리까지 표시한다. 수행력 자체는 기존 0.1 단위 계산을 유지한다. 피로와 기본 스탯은 현재 수행력을 통해 반영된다.

관련 능력이 모두 같은 값일 때의 계산 예시는 다음과 같다. 다른 능력 조합·컨디션에서는 달라진다.

| 현재 수행력 | 전공 숙련 50 | 전공 숙련 100 |
|---|---:|---:|
| 20 | 1.04배 | 1.05배 |
| 40 | 1.19배 | 1.28배 |
| 60 | 1.61배 | 2.01배 |
| 80 | 2.65배 | 4.52배 |
| 90 | 3.74배 | 7.98배 |
| 100 | 5.66배 | 16.00배 |

모든 관련 수행력과 숙련이 100일 때 16배는 현재 능력 범위와 지수식에서 도출되는 값이다. `maximum` 상수로 잘라내는 구조는 아니다. 한 관련 수행력이 0이면 기하평균이 0이 되어 1배다. 높은 능력 하나만으로 약한 관련 능력을 완전히 대체할 수 없다.

지원에 합격한 전공이 있는 수련·경력 단계의 임상·연구·업무 활동에서 적용한다. 대학·은퇴·미수련 경로·공부·교류·휴식의 배율은 1이다. 지원 점수는 기존 ±8점 보정을 유지한다. 자격이나 면허를 새로 부여하지 않는다.

- 관련 능력의 양수 연습량과 해당 전공의 숙련 성장량을 증폭한다. 기존 성장 체감과 단계별 상한을 유지한다.
- 월 활동의 양수 경험치, 임상·연구 선택 결과의 양수 경험치와 수련 숙련 보상을 증폭한다. 정수 저장 항목은 반올림한다.
- 분기 활동과 임상·연구 선택에서 주된 스탯의 양수 성과 보상을 증폭한다. 기존 100 상한·유지 부담·피로·실패 손실은 유지한다.
- 개원과 연구의 **양수 추가 성과 수입**을 증폭한다. 고정급·기본 수입 전체에 곱하지 않는다. 손실은 증폭하지 않는다.

활동 아래에는 해당 활동에 실제 적용되는 배율을, 능력 창에는 전공과 관련 능력 및 임상 활동 기준의 배율을 표시한다. 화면 조회는 상태나 난수를 바꾸지 않는다. 배율은 저장된 전공·능력·숙련·컨디션에서 재계산하며 저장 필드나 이전 사건 판정 규칙을 추가하지 않는다. 난수 추첨 횟수·월 중복 처리·선택 중복 처리는 기존 구조를 따른다.

검증: 지수식의 단조 증가·증가폭 확대·작은 숙련 변화 반영·전체 수치 범위의 유한성 검사를 추가했다. 전체 Vitest 실행은 451개 중 450개 통과했다. 추가 업무의 고정 수입만 비교하던 기존 테스트 1개는 피로에 따라 실제 추가 성과 수입도 변하는 것을 반영하지 못했다. 실제 장부의 성과 수입을 정산한 뒤 고정 업무 수입을 비교하도록 수정하고 관련 진로·시너지 86개를 재검증해 모두 통과했다. 수정은 테스트에만 적용했으며 전체 재실행은 반복하지 않았다. TypeScript 전체 검사와 분리된 Vite 빌드도 통과했다. 독립 Node 진로·경제 37개는 해당 코드가 바뀌지 않아 직전 통과 결과를 재사용했다. 빌드는 `.orchestrator/specialty-synergy-build`이며 500kB 초과 번들 경고는 남는다. 장기 균형과 실제 브라우저의 플레이 체감은 별도 조정 대상이다. UI는 서버 렌더링으로 문구와 읽기 전용 동작을 검사했으며 실제 브라우저 검수와 공개 배포는 수행하지 않았다.
