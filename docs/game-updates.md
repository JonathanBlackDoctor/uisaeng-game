# 플레이 중 업데이트 안내

2026-10-13 사용자 요청 `in-game-update-toast-v1`을 구현했다. 작은 토스트에 “새 버전이 있습니다.”와 업데이트·나중에 버튼을 표시한다. 개발 서버에서는 감시하지 않고 운영 빌드에서 동작한다.

- 게임 소스·진입 HTML·의존성·빌드 설정의 SHA256을 운영 코드와 `version.json`에 함께 넣는다. 사용자가 화면을 보고 있을 때 1분마다 확인하고, 다른 탭에서 돌아왔을 때도 확인한다. 반복 복귀 요청은 최소 15초 간격으로 묶고 동시에 여러 요청을 보내지 않는다. 5초 안에 응답하지 않거나 오프라인·404·잘못된 JSON이면 조용히 다음 확인을 기다린다.
- 같은 버전에는 알리지 않는다. 새 배포가 감지돼도 강제로 멈추거나 새로고침하지 않는다. 나중에는 같은 버전 안내를 5분 동안 미루며, 그 사이 다른 새 배포가 나오면 알릴 수 있다.
- 업데이트 버튼은 현재 작업이 저장 중일 때 비활성화된다. 버튼을 누르면 기존 전역 잠금으로 다음 게임 입력을 막고, 최신 상태를 IndexedDB 트랜잭션으로 먼저 저장한다. 성공한 뒤 동일 주소에 버전 쿼리를 붙여 교체 이동한다. 기존 쿼리·해시·데이터베이스·회고를 유지한다. 다른 탭의 변경과 충돌하거나 저장에 실패하면 이동하지 않고 토스트에 원인을 표시한다.
- 중요한 선택이 열린 동안에는 native dialog 안에 안내를 넣어 키보드와 터치로 적용할 수 있게 했다. 선택을 접었을 때는 대기 카드 위에 표시한다. 상세 능력·새 게임 확인 중에는 안내를 잠시 숨기고 닫은 뒤 보여 준다. 열린 선택 자체는 해결하거나 다시 추첨하지 않는다.

검증: Vitest274/18파일, tsc -b 및 Pages base 로컬 빌드 통과. `.orchestrator/hq016-update-tests.log`. 업데이트 감지·잘못된 응답·오프라인·비활성 탭·요청 간격·정리·선택 저장·다른 탭 충돌·실패 시 이동 차단을 포함한다. Node37의 게임 수식 소스는 이전 검증 후 변경하지 않았다.

실제 브라우저에서는 독립 임시 origin에서 운영 빌드 A→B를 교체했다(B는 모의 배포용 버전만 변경). 자동 확인으로 토스트가 나타났다. PC/아이패드1024×768·모바일390×844 화면, 모바일 토스트 약246×66px, native 중요 선택 안의 안내를 확인했다. 열린 동아리 선택에서 업데이트를 눌러 새 JS가 로드되는 것과 선택 제목·후보·나이·능력치가 정확히 유지되는 것을 확인했다. 적용 후 알림이 없어졌고 밴드 선택·저장이 이어졌다. Console warn/error0. `.orchestrator/ui-qa/hq016-update/qa.json`과 JPG에 근거를 남겼다. 임시 서버·검수 탭은 종료했고 기존 5195·5173·공개 저장은 보존했다. 실제 iPad Safari 기기 검수 및 실제 GitHub Pages 배포 전환 검수는 아직 하지 않았다.

공개용 로컬 빌드는 `.orchestrator/hq016-update-build`의 `index-BwlXymQ3.js` / `index-Vmg45jdr.css` / `version.json`이다. JS554.01kB 크기 경고가 남는다. 이 기능이 없는 이전 공개 버전에는 먼저 한 번 새 버전을 로드해야 안내 기능이 설치된다. 현재 공개 쓰기는 인간의 별도 명시적 승인 대기 상태다.
