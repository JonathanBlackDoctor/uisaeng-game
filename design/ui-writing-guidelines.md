# 화면과 문구 공통 기준

2026-10-12 사용자 확정: “게임 화면의 디자인은 반드시 심플해야 하고 문구들에서 AI가 작성한 것 같은 느낌이 안 나고 자연스러워야 해. 이건 에이전트들이 다 알 수 있도록 해.”

모든 UI·콘텐츠·개발·검수 작업에 적용한다.

- 한 화면에서 지금 필요한 상태, 사건, 선택을 먼저 보여준다. 같은 뜻의 제목·부제·배지·안내를 반복하지 않는다.
- 색·테두리·카드·아이콘은 구분에 필요할 때만 쓴다. 생활 장면과 인물의 움직임은 살리되 조작을 방해하는 장식은 줄인다.
- 버튼은 행동을 바로 알 수 있는 짧은 말로 쓴다. 예: 시작하기, 일시정지, 활동 변경, 기록 보기.
- 사건은 구체적인 상황과 상대의 말·행동으로 쓴다. 선택지는 실제로 할 행동을 자연스러운 한국어로 쓴다.
- “당신만의 이야기”, “나답게 걸어온 길”, “삶의 갈림길”, “완벽한 선택보다” 같은 상투적인 감성 문구, 과장된 비유와 반복 응원을 쓰지 않는다.
- 게임 화면에 개발 과정·도구·오케스트레이션·프롬프트 용어를 넣지 않는다. 필요한 개발 상태와 시험 수치 설명은 도움말·개발 문서로 분리한다.
- 근거가 없으면 아무것도 표시하지 않는다. 근거가 있으면 출처 링크가 달린 한 문장만 표시한다. 별도 근거 제목·설명·펼침 메뉴를 붙이지 않는다.
- 실제 게임 상태에 없는 수치·인물·경력을 만들지 않는다. 표시 스탯은 건강·행복·지식·관계다.
- 검수할 때 PC와 모바일에서 중복 문구, 긴 버튼, 불필요한 설명, 감성적인 상투어를 확인한다. 실제 사건의 맥락과 필요한 정보는 삭제하지 않는다.

이 기준은 이전 작업 명세의 꾸밈·문구 예시보다 우선한다. 원작의 시간 흐름·선택 경험과 생동감 있는 장면 방향은 유지한다.
